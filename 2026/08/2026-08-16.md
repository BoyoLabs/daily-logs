# 2026-08-16

## Retired the automated nightly daily-log push

Traced a missed nightly push to the unattended job's own login having expired overnight, then found that renewing it isn't possible headlessly — the re-authorization step needs to print a link and wait for a response, and a backgrounded job has no channel to prompt through or hear back on. Killed the stuck attempt, confirmed nothing else was disrupted, and manually distilled and pushed the previous day's entry by hand. Along the way fixed a leftover file-ownership slip in the log repo from an earlier session, and retired the automated push entirely in favor of a standing habit: review and publish the previous day's notes together in the first session of each day.

## Print server: storefront for personal designs

Added a storefront tab to the print server alongside the existing print queue, letting the owner list his own designs for order — title, description, price, and an STL, reusing the same upload/orient/slice pipeline the queue already uses, except sliced files are kept permanently since a listing can be ordered more than once. A visitor can preview a listing in 3D and order with just a name and phone number, dropping straight into the print queue without touching the friend-account slot limit. Because that's also an abuse surface, added a queue cap on unprinted storefront orders, a per-connection rate limit, a block on repeat open orders for the same design from the same number, and a honeypot field — testing against an isolated scratch copy caught a real bug (a rejected duplicate order was still burning a rate-limit slot) before it reached production. Deployed live without disrupting the printer connection or existing queue.

## Storefront listing photos, captured in the orient tool

Added a real product photo to each storefront listing after the toolpath preview alone proved too coarse to show fine surface detail. Rather than a separate photography step, capture was folded into the existing orient step — orbit the part into a good pose and hit Capture photo, which becomes the listing's card image. The first real listing was deleted at the owner's request to redo with a proper photo; two listings now have real captured photos live.

## Orient-tool camera controls: mobile fix and real panning

Added camera-only look-around controls to the 3D orient tool used across the upload flow and both storefront forms. On desktop, added middle-click-drag alongside the existing right-click orbit; on mobile, where a single-finger drag had always both looked around and reoriented the part — occasionally reorienting a print by accident — two-finger drag now orbits only, with one-finger drag left untouched and a fumbled one-finger start cleanly handing off into two-finger orbit mid-gesture. A same-day correction reworked middle-click from a second orbit control into true panning (sliding the view itself, scaled to zoom level) once it became clear that composing the new listing photos needed the plate brought into frame under a part, which orbiting can't do. Both changes deployed live without disrupting the printer connection or queue.

## Print server: site-wide pause-orders switch

Added a single toggle for the owner that pauses all three ways a stranger can add something to the queue — STL upload, link-based quote request, and storefront order — while never blocking the owner's own submissions, showing a plain-language "paused while we catch up" banner everywhere when active. Saved to disk rather than held only in memory, so an unrelated app restart can't silently un-pause it. Verified live: non-owners can't flip it, all three paths block with the message when on, the owner's own submissions pass through, and the paused state survived a real restart.

## Homepage now links to the storefront

The print server's storefront had no link anywhere on the public site — added one sentence and a link on the Digital Fabrication arm card, matching the existing low-key inline-link style used for the Open Source arm's GitHub link. Confirmed live after the normal restart.

## Print server: combined multi-part print jobs

Added admin-only support for uploading several parts at once, orienting each independently through the same orient tool, and packing them onto one build plate for a single combined slice-and-print job instead of one part per print. Packing lays parts out without overlapping (largest first, generous spacing for tree-support fan-out) before handing the arrangement to the slicer as one job; a real test slice confirmed the slicer handles multi-part input correctly before wiring it into the site. End-to-end testing against throwaway parts on the live app produced correct combined output with no leftover files, correctly rejected a non-admin attempt and a mismatched-input attempt, and the test job was cleaned back out of the real queue afterward. Not yet tried hands-on in the browser or run as a real physical print.
