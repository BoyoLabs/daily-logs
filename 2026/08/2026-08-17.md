# 2026-08-17

## Statement of intent, drafted and published

Talked through what Boyo Labs is actually for, long-run: never customer-facing beyond the small print-order arm, funded by the investing side rather than any product, and built to be taken seriously as real work without needing a business model to justify it. Turned that into a short formal statement of intent and published it in two places — the GitHub organization's profile page and a new page on the homepage.

## A routine service restart stopped working, traced to the previous night's kernel update

Deploying the new statement-of-intent page surfaced a quirk: a service restart that has always worked started failing silently, for no obvious reason. Worked around it through the admin dashboard's own restart control while digging into the real cause, which turned out to be a kernel update installed and rebooted into the night before — the new kernel's default security-module list had silently dropped a module some tooling depends on for exactly this kind of restart, and its absence caused the failure. Fixed with a one-line addition to the boot configuration to re-enable that module, then a clean scheduled reboot to apply it. Verified afterward that the module was active again and the original restart problem was fully gone.

## Remote-desktop connection relay, fixed and root-caused

While lining up a fallback way to reach the machine before the reboot above, found the remote-desktop stream's connection relay down — something that's apparently needed a manual restart most days recently. Restarted it and traced why it keeps happening: unlike every other service on the box, this one has no automatic self-heal check, so it only ever comes back at a full reboot instead of within a few minutes like everything else does. Gave it the same automatic check the rest of the box already has — caught it down again mid-fix, which doubled as a live test that the check actually catches and restarts it within seconds.

Went back afterward to actually pin down why it kept dying, instead of assuming. A month of system logs turned up no crash trace at all for that process — no out-of-memory kill, no crash signal — and the machine itself had only rebooted twice in that whole window, so a reboot-driven explanation doesn't cover a near-daily pattern either; the relay's own log showed far more restarts than that, pointing at manual restarts during past debugging sessions rather than silent nightly deaths. Separately, double-checked an older and unrelated failure mode for the same remote-desktop stream — a signaling wedge first hit and fixed weeks ago — and confirmed its fix (waiting for an audio socket before launch, plus a log-signature check that force-restarts if the wedge happens anyway) is still live and hasn't had to fire since. Between the two, the stream's two known failure modes now both self-heal; a fresh outage from here points at something not yet seen rather than either of these.

## Dashboard restart controls simplified to one button per service

The admin dashboard's per-service restart panel used to take two separate clicks to fully cycle a service — one for its app, one for its tunnel. Consolidated both into a single combined restart, tunnel first so a dashboard self-restart can't cut off a still-pending tunnel restart, cutting it down to one button per service. Verified live against a real service, including the trickier case of one that shares its tunnel with another — a chase down what looked like a real failure turned out to be a self-inflicted false alarm from a verification command matching its own text instead of a real process, with zero actual bugs once retested cleanly.

## A task calendar added to the admin dashboard and its mobile view

Boyo Labs had accumulated a real set of recurring obligations — a daily log push, a daily balance update, a biweekly portfolio update — tracked only by memory and convention, with nothing that actually put them on a calendar. Built a Calendar tab for the admin dashboard and a matching one for its mobile companion view: one-off and recurring tasks (daily, weekly on chosen days, a fixed weekdays-only preset, biweekly, monthly, or a custom day interval), with each occurrence toggleable between done and not-done without deleting the underlying recurring rule. Getting the mobile view right took a few passes. A report of task chips overflowing their card turned out not to be a caching problem — ruled that out by round-tripping a real login through the live public site and confirming the fix was already being served — but a genuine CSS grid sizing quirk, where a long task title with no line-wrapping was forcing a whole row of day cells wider than their container; the real fix was telling those cells to clip instead of stretch. Also swapped the three-tap done/skipped/pending cycle for a plain done/undone toggle so an accidental tap takes one tap to fix instead of two, added a weekdays-only option as its own explicit choice rather than a picker hidden behind another one, and replaced the mobile view's cramped weekly grid with a one-task-per-row daily list — the actual fix for tasks being too small to tap accurately — keeping the weekly view around as a secondary toggle.
