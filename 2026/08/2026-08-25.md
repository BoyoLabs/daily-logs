# 2026-08-25

## Mobile chat frontend for Claude Code

Built a new phone-friendly chat interface to a Claude Code instance — real
chat bubbles instead of a terminal, tool actions show up as approve/deny
cards by default with a per-chat "full auto" toggle for when zero friction
is wanted. It needs broader system access than the other apps on the box,
so it's held to a stricter default (every action needs a tap unless auto
mode is on) rather than inheriting the looser trust the other apps run
under. Along the way, discovered that Ollama's CLI has a first-party way to
point a coding-agent harness at a locally-run model instead of the cloud
one, so the same chat interface can optionally run against a local model
too — works, though noticeably slower on this box's hardware without GPU
acceleration for it. Also added markdown-aware rendering for code Claude
sends back — syntax highlighting, a copy button, proper code-block styling
— instead of flat monospace text.

## Retired the troubleshooting-script host

Tore down the internal troubleshooting-script host that's been serving
copy/paste scripts for day-job case work — it was scoped as day-job
tooling rather than a Boyo Labs project, so retiring it once the
day-to-day need passed it by was always the expected endpoint, not a
surprise call. Stopped the app and its tunnel process, pulled the cron
entries and the tunnel-watchdog restart rule that kept it self-healing,
deleted its tunnel config and credentials, and removed the tunnel
registration from Cloudflare outright rather than leaving it sitting idle.
One loose end: the DNS record for it is still parked at Cloudflare
pointing at nothing (the tunnel CLI can add DNS routes but not remove
them), so it now dead-ends with a server error instead of resolving
cleanly — harmless, just needs a cleanup pass in the Cloudflare dashboard
eventually. Left the app code and its helper scripts in place rather than
deleting them outright, same as how a couple of earlier one-off services
were retired — inert leftovers cost nothing to keep around and save a
rebuild if the tool's ever needed again. Logged and closed a ticket for
the work, per how infra changes get tracked here.

## First real test drive of the mobile chat frontend

Put real weight on the mobile chat interface built earlier today — sent a
basic script to check the approve/deny permission bubble, flipped on full
auto mode and confirmed actions still stay visible instead of going silent,
sent a real data table as a rendering test, and uploaded a photo to check
that path end to end. The photo upload worked cleanly both ways. Turned up
three rough edges along the way: a markdown table rendered badly on the
mobile screen, a "message exceeded maximum buffer size" error showed up at
some point in the session, and — the more interesting one — a full reply
describing the uploaded photo was generated correctly but never actually
reached the client, with no error shown at all, so it looked like nothing
had been sent back. Logged all three as a ticket to dig into later rather
than chase them mid-session. None of it blocked getting through the test
plan, and the practical outcome stands: there's now a working mobile path
to run the server through an assistant, not just read a dashboard passively.
