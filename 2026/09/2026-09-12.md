# 2026-09-12

## A new "AI-native app" for a full server status brief

A casual "how's the server looking?" turned into building a proper
status-check tool. The first pass was built as a standalone terminal
program, matching the existing family of small command-line tools already
living on the machine — but the actual want was different: something that
runs *in conversation* with the AI, not a separate program with its own
screen. The terminal-app draft was scrapped and rebuilt as a markdown
"app" file instead — a spec the AI reads and executes live, gathering
server health, tunnel status, open tickets, pending system updates, and
the daily-log publish state, then rendering it all as one aligned,
source-code-styled status block rather than a table.

A genuine bug surfaced before it ever shipped: the app's data-gathering
commands assumed a home-directory shortcut that silently pointed at the
wrong place when the executing session ran as a different local account
than expected — an easy way to fail quietly (empty results, no error) if
it had gone untested. Caught by actually running the thing rather than
trusting it on paper, and fixed by switching to explicit paths throughout.

## Daily-log gap traced to a quiet stretch, not a broken process

Running the new status app flagged the daily log as a couple of days
behind. Checking directly found no capture notes waiting for the prior
day at all, and the log's own history confirmed nothing had been queued —
a quiet stretch rather than a broken pipeline. This entry got drafted on
the spot as a result, held back from a same-day push per the standing
rule — it'll go out with the next morning's normal check instead.
