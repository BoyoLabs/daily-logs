# 2026-09-08

## Daily log capture rules rewritten

The rule for what counts as a loggable moment got reworked. Previously only builds,
fixes, and config changes qualified, with conversation explicitly excluded — but a lot
of the real work here is talk that leaves no artifact behind: investigations that end
in "no," ideas scoped and parked, observations about how the collaboration itself is
going. The new bar is two tests, both required: did the conversation land on something
durable (a conclusion, a decision, a reversal, an option ruled out — dead ends count,
"had an interesting chat" doesn't), and is the subject the lab rather than the person.
That second test turned out to matter more than expected — the old "no conversation"
wording had been quietly doing privacy work the whole time, and loosening it needed an
explicit personal-content exclusion to replace what it was covering.

Two standing habits that were already being followed got written down for the first
time, since the reasoning had never been on paper. First: a day's entry never gets
pushed on the day it happened, even on explicit request — calling a day finished is a
prediction, and "confidence the day is over" is regularly followed by one more thing
that needs doing. Waiting a night costs nothing; publishing early costs either an
incomplete record or a second commit stapled onto whatever came after. Second: capture
stays incremental through the day rather than an end-of-day summarization pass, because
a draft file on disk survives context compaction and session boundaries in a way a
"summarize everything at the end" approach doesn't — and deferred summarizing tends to
keep the conclusions but lose the wrong turns, which are usually the interesting part.

## Stale DNS records left in place, on purpose

Decided not to treat leftover DNS records from decommissioned services as a cleanup
chore. The usual reason to worry about a stale record — someone else claiming what it
points at and inheriting the hostname — doesn't apply here, since the tunnel
identifiers those records reference are randomly generated, account-bound, and not
claimable by anyone else. A retired record just fails closed with a gateway error
instead of becoming somebody else's front door. The real cost is that the DNS zone
stops being an accurate map of what's actually live, which only bites when trying to
recall what exists or reuse an old hostname — so cleanup stays opportunistic and
batched rather than owed.

## Filament runout: from silently printing air to auto-pause

Tracked down why the 3D printer kept extruding after running out of filament instead
of catching it. Not a broken or missing sensor — the firmware is stock Marlin with
runout detection compiled in and switched on, and the sensor reports its state
correctly on demand. The catch: the firmware only checks that sensor while it believes
a print is underway, and it decides that from an SD-card print or an internal job
timer, neither of which a print streamed over USB from the print server ever starts —
confirmed by finding zero instances of the timer-start command across a full ~1.5
million-line print. So the printer wasn't ignoring the sensor; it didn't think it was
printing. The fix needed no firmware change, since a direct status query reads the
sensor pin live regardless of print state — just needed polling from the host side.

What started as "notify me on runout" grew into three features that turned out to
share one mechanism: auto-pause on runout, a manual pause button, and a cancel that
gets the hot nozzle off the abandoned part instead of leaving it to melt a crater into
it. Putting the park routine in the print host's own pause lifecycle hook — rather than
in any one caller — meant a runout pause, a button press, and a cancel all run the same
retract-lift-park sequence, and any future way to pause inherits it for free. The head
parks at the front corner where the purge line starts, so ooze lands on bare bed and
the extruder stays reachable for a filament change without leaning over the print.

## Making the runout alert trustworthy

Notification is event-driven, not polled: since the printer now pauses itself on
runout, the pause is the trigger, and the sensor only gets read afterward to explain
why it stopped — so normal printing adds no extra traffic to the printer at all until
something has actually gone wrong. Resume also refuses to run while the sensor still
reads empty, closing off the obvious failure mode of resuming before reloading and
quietly printing air a second time.

A plain question about whether the email actually arrives caught a design weakness:
it did, but only as a side effect of the pause, which meant the one genuinely unverified
assumption in the whole chain — whether the firmware's actual runout signal is a variant
the print host recognizes — could take the notification down with it. If it turned out
to be an unrecognized variant, there'd be no pause and therefore no email, and that
silence would be indistinguishable from everything working fine. Decoupled the two: the
alert now fires from its own slow sensor poll during printing regardless of whether a
pause happened, with wording that says which case occurred, so the alert doubles as the
test for the unverified part. Added a second state check before alarming too, since a
correctly-handled runout could otherwise race into a false alarm — and one false "it
didn't pause!" alert is the fastest way to train yourself to ignore all of them.

**Open thread:** the whole chain is verified in software but not yet against the
physical machine — the printer was out of reach today. Specifically unproven: which
exact signal variant the firmware emits when the sensor actually trips (the host
handles one variant natively and ignores two others), and a real park-and-resume on a
sacrificial print. The purge-on-resume distance is deliberately left unset rather than
guessed, since it depends on a physical measurement from sensor to nozzle. Also noticed
the printer's serial debug log has grown to roughly 180MB in two days with no bound —
worth capping before it becomes its own problem.
