# 2026-09-01

## Procedural goblin figurine in Blender

Wrote a script that builds a goblin figurine from scratch in Blender headless and
exports a print-ready STL — no hand modelling, no sourced mesh. Soft anatomy is a
metaball skeleton (torso, limbs, skull, hooked nose), everything that has to stay
sharp (ear points, tusks, claws, eyes, plinth) is mesh primitives, and the two are
fused by a voxel remesh so the union comes out watertight for free. Eye sockets,
mouth line and the flat bottom are the only real booleans.

Iterated blind over ssh by rendering four orthographic views plus head close-ups
after each build and just looking at the PNGs. Notable dead ends: metaball `radius`
is the field-of-influence radius, not the visible one (surface lands at 0.575x), so
the first build was a cloud of disconnected beads; arms posed one element per joint
came out as a bead chain until an interpolation helper filled the gaps; a nose built
from two overlapping cones was always a flat fin rather than a hook, fixed by making
the nose a metaball chain instead; and tusks kept hanging below the chin because the
jaw was too short to bury their cone bases. Final model is 80mm tall, ~225k
triangles, verified watertight, published to the file server.

## A chess puzzle battler, built start to finish

Built and shipped a new public-facing service: a chess puzzle racer where two
players work through the same ramping stream of tactics puzzles for three
minutes — one point for a correct solve, a wrong move ends that puzzle. An
empty queue after 20 seconds hands you a simulated bot matched to your own
rating instead of a wait. Friends, challenge-a-friend private matches, and a
post-game review showing every puzzle against the right line all shipped the
same day, on top of a 5.4-million-puzzle open dataset imported into its own
database file kept separate from accounts. Deliberately no live connections —
two people racing a clock independently is indistinguishable from polling
plus a locally interpolated countdown, and it avoids holding a long-lived
connection open through the tunnel.

Introducing a lose-a-point-for-a-miss rule quietly broke the difficulty ramp:
once a wrong move costs more than a right one earns, a puzzle is only worth
attempting when you're better than even money to solve it — which is exactly
even at a puzzle rated at your own rating — and the ramp climbed straight past
that line. The provably optimal play became "bank the easy points, then stop
trying," which gutted the bot's median score by two thirds in a game whose
whole premise is speed. Fixed by capping the ramp just under the player's own
rating rather than at it, so the back half of a match stays worth playing
instead of decaying into a coin-flip random walk. The bug was invisible
reading the code and obvious the moment the expected value per puzzle got
written out as a table.

## Real-browser bugs a curl test would never catch

Two bugs this build only turned up because it got driven through a real
headless browser instead of hit with plain requests. The board was built while
its container was still hidden, so it measured zero width and fell back to a
hardcoded square size; a later resize repositioned the pieces but never
redrew the squares, leaving two mismatched grids. A `ResizeObserver` — the
only reliable way to learn a hidden element's real geometry once it appears —
fixed it. Separately, making every player name in the UI a profile link meant
the opponent's own name on the match screen became clickable too, and tapping
it mid-race silently abandoned an unrecoverable three-minute match; navigation
now gets suppressed while a match is live. Both were invisible to any
request-level test and only showed up once the full sign-up → queue → play →
review flow got driven end to end.

## Infrastructure snags: the same tunnel trap, plus a new variant

Routing DNS for the new tunnel by its bare name silently pointed at a
completely unrelated, older tunnel — the same trap every new tunnel on this
box has hit before, fixed the same way, by routing with the full tunnel ID
instead. A new variant turned up alongside it: creating the tunnel while
elevated left its credential file owned by the elevated account, so the
tunnel daemon — which runs as the regular service account like everything
else here — refused to start with a permission error that gave no hint about
ownership. Same family as the standing rule that elevated edits under the
regular account's home break that account's own services, just easy to miss
because creating a tunnel doesn't look like editing a file.

Separately, a report of a null-property crash and a vanished leaderboard
turned out to be a CDN quietly overriding this box's cache headers — the
origin asks browsers to revalidate every time, but the edge forces a
four-hour hard cache on JavaScript and CSS while leaving HTML alone. A
visitor could load the newest HTML next to hours-old JavaScript, and any
element the new page had removed became a null lookup in the stale script.
Fixed by fingerprinting asset URLs from the files themselves, so editing a
file is the version bump and no cache lifetime anywhere can serve a stale
copy of a URL that no longer exists. The other services on the box share the
same exposure; they just haven't been bitten yet because their pages and
scripts tend to change together.

## Accounts, security, and going fully public

Added player profiles (rating, record, accuracy, an editable bio, a
re-encoded 256px avatar so nothing but pixel data ever gets stored back), and
made the simulated bot blend in rather than announce itself: no queue
countdown, no scoreboard tell, ordinary-looking handles reserved at signup so
nobody can impersonate one — but its own profile discloses plainly that it's
a bot, with no invented record. Also pulled the site-wide "who's online"
roster, since on a small player base a live headcount is the first thing you
don't want a new visitor reading off the front page; per-friend presence
stayed.

Added email verification and password reset — the one fully open-signup,
no-gate service on the box, a deliberate departure from how everything else
here is gated. Reset and confirmation tokens are stored hashed and single-use,
validated atomically so a double click can't win twice, and the
forgot-password endpoint answers identically whether or not an account exists
so it can't be used to check who's registered. A file-based mail switch let
the whole signup-confirm-reset flow get driven through a real browser without
mailing anyone, and got kept for the next time someone reports a missing
email. Player profiles then became shareable public links that work with no
login at all — nothing private lives on one, and a profile link that requires
an account isn't really shareable.

## Torn down the same day: a "well, duh" moment

Decommissioned the whole service the same day it was built. Working through
where it could realistically go — legitimacy, ratings people would trust,
whether to advertise it — landed on the plain fact that a near-identical
puzzle-racing mode already exists at real scale, with ratings people already
trust: it was, in short, basically the same thing already done better
elsewhere. Rather than leave it running unused, it got pulled in full —
processes stopped, the tunnel deleted, the 5.4-million-row puzzle database and
its launch script removed, and every reference to it scrubbed from cron, the
dashboard, and the backup script. It worked, end to end, exactly as designed;
it just didn't need to exist next to something that already does the job at a
scale this box never will. The design work — the scoring/ramp model, the
unadvertised-bot approach, the honest disclosure pattern — is kept on record
in case a similar build makes sense again.
