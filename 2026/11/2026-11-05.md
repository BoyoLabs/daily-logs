# 2026-11-05

## Off-site backup moved to Google Drive

The daily emailed backup had been failing since 10/30, when the snapshot outgrew the email attachment cap (mostly chat transcripts), so the copy that doesn't depend on the server quietly didn't exist for a week. Keeping it on the same disk was ruled out as not off-site. The nightly job now encrypts the snapshot and a new file server archive (~500MB together), uploads both to Google Drive, checks the upload against a checksum, and only then removes the previous night's copies. The Google sign-in's redirect can't reach the server from a phone, so setup was done by pasting the failed redirect URL back and exchanging the code directly. Failures now show in red on the dashboard and send an email, since "only in a log file" is how the old path broke unnoticed.

## File server archive added to the nightly backup

The nightly backup also writes a separate zstd-compressed archive of the file server's full contents (~576MB raw to ~422MB), kept out of the emailed snapshot because it is far over the attachment cap. It is stored locally and on the USB backup drive with its own retention, and was verified by extracting and diffing against live storage: all files identical.

## USB backup drive had silently stopped, now has a dashboard card

Nightly copies to the plugged-in USB drive had stopped two months ago: the scheduled job's stripped-down environment lacked the tool used to detect the drive, so it assumed the drive was absent whenever it wasn't already mounted. Fixed, verified under that same environment, and the drive caught up. A new USB Backup card on the dashboard and glance page scans for drives, lets one be picked, and copies the newest backup with readable dated names, keeping the last 10 and deleting the oldest only after the new copy is read back and verified. The nightly job uses the same code, so there is one naming scheme and one retention rule. While building it, a bug surfaced: the file server archive would have swallowed the whole USB drive whenever it was linked into the file server, so it now skips other drives.

## Chat console "restarts" fixed

The console wasn't crashing: by design it started a fresh agent process for every message and shut it down when the turn ended, which killed background jobs each turn. The resumed agent then reported those killed jobs and sent an early, empty "turn finished" signal; the console took it as the end of the turn and shut the agent down mid-work, producing the "stream closed" failures. Each tab now keeps one agent process alive across messages with a continuous reader, so background jobs survive and their follow-ups show up in the chat on their own. Stop now interrupts the turn without killing the process, and idle sessions close after a timeout with a cap on how many stay alive. Tested end to end against scratch data before deploying.

## Perfection star v2

The test fit of the travel-board pieces showed the parallelogram and rhombus dropping straight in, but the 5-arm star sitting on the rim. Re-measuring showed the arms are not evenly spaced (70-75 degrees, not 72) and sit up to about 0.4 mm off-center, which used up the clearance at the thin arm-tip fins. The v2 keeps the top plate and replaces the lower body with a 3 mm core plus short 1.3 mm fins laid on each arm's measured angle. Lesson: on narrow multi-arm shapes, angular error at the tips matters more than width error, so make the locating part short and forgiving rather than an exact copy. Not yet test-printed.

## Mini cornucopia figurine

A ~50 mm cornucopia, meant as a small hide-and-find print, was designed in OpenSCAD from a reference photo: a horn built from hulled spheres along a tapering curve, a sine wobble on the radius for woven rows, a braided rim, and a produce pile domed out of a shallow recess so there are no inner overhangs. Two gotchas. The hulled-spheres horn previewed fine, but OpenSCAD 2021's full render never finished in 20+ minutes, since it had to union 120 convex pieces; rebuilding it as one swept polyhedron brought the render to about 60 seconds. And the first mesh came out as two solids because a spilled berry touched nothing, which a connected-component check on the STL caught. Not yet printed, to see how the tiny details come out.

## Boyo Labs Esc keycap

An Esc keycap with the Boyo Labs chip logo was designed in OpenSCAD for the Keychron board, with MX-style cross stems read off photos of the bare switch. The logo is cut as a prism intersected with the dish cylinder pushed down by the depth, so it follows the curve at a constant depth instead of cutting flat. It prints upright with no supports, and a separate three-stem fit test (0.10/0.15/0.20 mm clearance) lets the fit be tuned without wasting a full cap. The preview caught one bug: chamfering the cross mouth by hulling the whole "+" fills its corners and makes an octagonal crater, so each bar has to be hulled separately. At ~11 mm wide the logo's pins are about 0.45 mm, right at the limit for a 0.4 mm nozzle.

## 3D viewer touch controls on phones

In the file server's 3D viewer, a one-finger drag on a phone rotated the model a tiny bit and then stopped, and there was no pinch-zoom. The viewer never told the browser it handles touch gestures itself, so the phone took each drag over as a page scroll partway through. Fixed, with input handling rewritten so one finger orbits and two fingers pinch-zoom, verified in an emulated phone.

## Printer case light at full brightness

The printer case light's on-brightness went from about 20% to 100%. The dim level was a leftover from when the light stayed on for long stretches; now that it gets toggled off when not needed, full brightness when on makes more sense. Shared by the print app and dashboard toggles, verified on the printer.

## Contact form spam looked into

A gibberish message arrived through the Woodsman Ways contact form. The server log showed a scripted submit (page load, form, POST in about two seconds), the same background noise as the steady scanner probes the site already gets. The form was confirmed safe against email header injection and script injection on the page, so it was judged spam rather than an attack, and nothing was changed.
