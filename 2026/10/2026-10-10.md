# 2026-10-10

## Voice mode on the agent console

The agent console gained two ways to talk to it. A mic key on the prompt line dictates into the input box for review before sending, and a hands-free mode runs a full loop: speak, it sends when you stop talking, the agent does the work, the reply is read aloud, and the mic reopens for the next thing. Tapping the key cuts a reply short, and saying "stop listening" ends the loop.

## Fully local speech instead of browser or paid APIs

Speech-to-text runs on Whisper (the small English model) and the voice on Piper, both on the server's own CPU. The browser's built-in speech APIs were ruled out because audio leaves for a third party, support varies by browser, and the voice differs per device; a paid speech API was ruled out on cost. Measured before committing: about 0.7 seconds to transcribe a 7-second clip and under 0.4 seconds to synthesise a 7-second reply, so the agent's own turn dominates the wait.

## Design calls behind the voice loop

Only the last message of a turn is read out, not the play-by-play. Spoken messages carry a hidden note asking for a short spoken-style summary and warning that the text is a transcription, so ambiguous or destructive requests get confirmed first. Silence detection is a simple adaptive loudness meter in the browser, backed by a real voice-activity filter on the server so room noise comes back as nothing rather than a hallucinated sentence. Voice mode is per device, never persisted, and does not switch auto-accept on by itself.

## Tested with a WAV file as the microphone

The whole loop was verified end to end by handing headless Chrome a WAV file as its microphone and driving the live page: it heard, transcribed, ran a command, spoke the answer, and went back to listening. It has not yet been tried on a real phone or handheld microphone, so silence timeout, voice choice, and reply length are still to be tuned after first real use.
