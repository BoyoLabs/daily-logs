# 2026-10-08

## The chat frontend rebuilt into a terminal-first agent console

The chat frontend was reworked from a chat app wearing a terminal theme into an actual agent console. The two-screen list-then-chat navigation is gone: one screen, a tmux-style tab strip with one tab per open session, and each tab showing whether its session is still running or blocked on an answer, so several agent jobs can run side by side. The session view is drawn in the agent CLI's own notation, and the design rule that came out of the conversation was "an actual terminal with clickables" — everything a keyboard-driven TUI does with arrows and escape became a tap target instead, including a slash-command palette that also lists installed skills.

Three same-day corrections followed. The first cut made the model picker look like plain text, which read as "the picker was removed," so it became a visibly boxed dropdown, with a second one in each session's footer. That reverses an August decision that a session's model is chosen once at creation: switching mid-session is now allowed, takes effect on the next message, and is printed in the session's own log so it can't happen unnoticed; context carried across a switch between two model tiers in a live test. Tabs then moved server-side so the same open sessions show on every device, and the home screen stopped listing past sessions, which forced a decision about what "close" means — closing keeps the record, and the resume picker (now the only history surface) brings the same tab back with its name, notes and mode. The takeaway: a control that gets used has to stay recognisable as a control, even in a terminal skin.

## A model list that updates itself

The agent CLI reports every model it can currently run in its startup handshake (about a third of a second, no inference, nothing billed), so the picker and the Claude-versus-local routing now come from that instead of a hand-written list kept in two places. It is re-read when the CLI binary changes, with the last good list kept for when the probe fails. This also fixed a latent routing bug in the old approach: any Claude model missing from the hand-written list was silently sent to the local model server. A session pinned to a since-retired model now falls back to the default with a visible notice instead of erroring forever, verified live with a made-up retired model.

## Day-to-day work moves to the console

The decision: lab work now starts in the agent console in preference to the browser terminal, mainly so picking a task back up from a phone stops feeling like a hassle. The terminal stays as a fallback. Behind it is a device-independence framing — the Steam Deck, a laptop and a phone are interchangeable windows into one server where all the work happens, and since sessions live server-side, switching devices is a resume rather than a restart.

## Ironman on the public demo hub, and a CDN caching catch

The Ironman game got its own card on the demo hub and opens with no login, and the game's build step now publishes the demo copy too so the hub always matches the current game. The first cut published the game as its normal folder of separate script and asset files, which passed its browser test locally, but checking response headers through the public URL showed the CDN caching script files for four hours while never caching the HTML page. For a game made of a couple dozen scripts that only work as a matched set, returning players would have gotten new HTML with a random mix of stale scripts. The same day it was replaced with a single self-contained page build, which is immune because the one thing the CDN never caches is the page itself, and verified with a headless-browser run both locally and through the public URL. A side fix: the game's source folder had never been in the nightly backup list.

## Remote control of the Steam Deck, tested

A connectivity test from the main machine to the Steam Deck over a temporary SSH link confirmed login works and that read-only checks run; nothing on the Deck was changed. A second test sent Steam's URL commands to open the on-screen keyboard, wait three seconds, then close it, and it worked on the Deck's screen, so remote-triggering Game Mode UI elements is viable.

## Small ones: print form hints and a tech-news app

The print server's slicing form gained two small italic hints beside the options, "20% is average" by infill and "PLA is the normal choice" by material, with the material hint naming whatever the default actually is rather than hardcoding it. Separately, a new AI-native app called tech-roundup was built: a single markdown file that has Claude run a live web-search pass and render a text version of a daily tech-news show. Its key design choice is a mandatory verification step (check the real story behind headline summaries, label shipped versus rumored, flag single-source claims) and a fixed section order. The fun-experiments search was the weak spot on its first run, mostly viral-tips spam, so the app is told to say so honestly instead of padding.
