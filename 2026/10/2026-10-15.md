# 2026-10-15

## Choosing a free 3D engine for AI-built games

The goal was an engine where the owner architects and Claude builds, so the deciding factor was how editable the project files are by an AI. Godot 4 won on plaintext scenes and scripts, a headless command line, and Blender already being on the box for models; Unreal and Unity were weighed and leaned out over license strings and binary, ID-heavy project files. A headless smoke test passed on the first try: a hand-written scene and script dropped a physics cube that settled at the expected height, proving the write-text-then-run loop works with no editor involved. Web export works too, but only on the lighter compatibility renderer and with a ~35-40MB engine download, so Godot is native-first with the web as a secondary target; a web-first game would point to Babylon.js instead.

## A walkable capability gallery, and a renderer bug found by bisecting

The first real project is a 3D gallery on the demo hub: 15 exhibits around a plaza covering materials, shaders, particles, physics, joints, procedural terrain, instancing, CSG, live shadows, imported Blender models, a spline coaster, an orrery, live render-to-texture screens, and 3D text, all generated in code and checked by screenshotting each one in a headless browser. Testing exposed a real bug in Godot's web renderer: shadow-casting point or spot lights combined with live camera-to-texture screens blew the whole floor out to white or black depending on view direction. Bisecting the exhibits with URL switches pinned it down, and the workaround was putting those lights on their own render layer that the screen cameras skip. On delivery, the engine is ~40MB raw but the edge compresses it to ~10MB, and every build gets fresh timestamped file names so cached scripts can never mix with a new page.

## Lanternfall: from a one-line pitch to a playable build

The game concept started as "dungeons only" and "strikes plus Crucible only" framings of two existing MMOs and landed on Lanternfall: a world swallowed by endless night, monsters that eat light, and players as lantern-bearers. Loot splits into a lantern and a flame (its light) with armor on top, each item gets exactly one manually triggered ability so the controls stay light enough for a handheld, and your own light always shows you while concealment comes only from gear. Pre-build decisions set the scope: first-person camera, light bolts as the basic attack raised from the lantern itself, and a v0 of one fogged arena, one monster, one item per slot, and a god mode. The desktop renderer's volumetric fog and shadowed lantern light were verified to render offscreen in software, so builds can be checked visually without touching the box's GPU.

## Eight versions in a day, and the bugs that shaped them

v0.1 was checked with an automated in-game self-test that screenshots every feature, which caught five visual bugs before the build went up. The first handheld playtest then found the controls dead apart from looking: input bindings created in code default to the first controller only, and the controller the handheld presents is usually not the first, fixed by binding every action to all controllers with a regression check that failed 8/8 on the old code and passed 8/8 on the fix. v0.2 added menus, a first-person staff and hands, four monster types including a boss, a first mission, 3v3 PvP, and bots, plus a small lobby service for parties, matchmaking, and the connection handshake while matches run player-to-player with one host and the lobby storing nothing. A two-copy network test on the server caught a handshake bug where a cleanup step told the lobby the player had left, so every connection attempt got dropped, found by logging each step.

## Playtest feedback drove the look

v0.3 replaced blocky stand-ins with characters built from free CC0 human-anatomy assets generated in Blender, animated in code on the real skeleton, and the early arm problems came from the models resting in an A-pose and bone positions being recomputed lazily, which showed up only once measured instead of eyeballed. v0.4 added a narrated opening cinematic using a local text-to-speech voice and a Creative Commons score, and rendering Steam library art from the engine exposed model flaws that got fixed at the source; v0.5 added a full sound layer and a relight mechanic. Stutters traced to regenerating a texture on every spawn and ~30 skeleton recomputes per character per frame, and the "bots stopped working" report turned out, once each bot was instrumented, to be bots only fighting monsters in a straight line of sight. v0.6 brought a second mission and PvP map in a mountain town, and an honest "looks like it was made by AI" comment drove v0.7: monsters became shrouded spectres with a fire-heart instead of posed bodies, and a walking test found hairpin corners on the mountain trail were actually steep banks and fixed them by blending heights through each turn. v0.8 gave lantern-bearers real outfits and made it possible to fight while carrying the light.

## Would it survive Steam review?

A look at Steam concluded the game would most likely pass, since review checks that the build launches and the store page is honest rather than judging quality. The must-dos are disclosing the AI-generated narration voice, shipping a Windows build alongside Linux, and probably moving matchmaking onto Steam's free built-in networking; listing costs $100 per game, refunded at $1,000 in sales, with Steam keeping 30%. Next up is more equipment, including rare chase items worth replaying for, and a first-person bug where the staff seems to spin when turning.
